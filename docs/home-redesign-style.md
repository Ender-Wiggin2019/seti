# Home 页面重设计风格说明

来源：用户提供的 `2223.PNG` 左侧 Home 页面视觉稿。本文只描述左侧 Home / 任务中心页面，不覆盖右侧设计系统展示页。

## 目标定位

Home 页面不是营销落地页，也不是普通房间列表。它应该是玩家进入 SETI 数字桌面前看到的 **任务中心**：用户能立刻理解当前可加入任务、进行中任务、自己参与的任务，并能创建或加入房间。

设计关键词：

- **低多边形深空场景**：背景不是纯黑，而是由星空、月面、岩石、行星、飞船、宇航员组成的真实空间环境。
- **游戏任务中心**：所有 UI 都服务于“创建任务 / 加入任务 / 查看任务状态”，不要引入泛化的 dashboard 语言。
- **克制的仪器感**：按钮、状态点、数字和标签像航天任务控制界面，但不要变成复古终端或电影 HUD。
- **首屏即产品**：首屏必须同时看到任务标题、状态统计、房间列表入口，不能只展示大图或宣传文案。

## 整体视觉风格

画面基调是暗色、冷静、低饱和。深空黑作为底层，岩石灰和金属灰负责建立 UI 深度，星尘白负责主要文字，行星橙与引擎青只在有含义的位置出现。

左侧画面的核心记忆点不是 UI 卡片本身，而是完整的“月面任务场景”：白色飞船横穿上方，地表上有宇航员和设施，右上有橙色低多边形星体或光束，远处有蓝色引擎轨迹。后续实现应优先保留这个场景感，而不是只复刻卡片边框和颜色。

色彩锚点：

| 名称 | 建议值 | 用法 |
|---|---:|---|
| 深空黑 | `#0A0E14` | 页面底色、远景空间、暗部渐变 |
| 岩石灰 | `#1A1F27` | 顶栏、卡片底、暗面岩层 |
| 金属灰 | `#2A303C` | 边框、分割线、次级控件 |
| 地表灰 | `#3A404D` | 月面、岩石、卡片背景图层 |
| 星尘白 | `#E6E6E8` | 标题、主文字、飞船高光 |
| 行星橙 | `#C7734A` | 行星、进行中标签、少量暖色焦点 |
| 引擎青 | `#2EC1C9` | 主按钮、选中态、可加入状态、引擎光 |

使用规则：

- 黑色必须有层次：星点、低多边形暗面、轻微蓝绿色冷调，而不是 `#000` 平铺。
- 橙色代表“进行中 / 行星地质 / 热光源”，不要用来做普通按钮。
- 青色代表“可操作 / 当前选中 / 可加入”，不要满屏发光。
- 紫色可以用于进行中数字或特殊状态点，但应少于青色和橙色。

## 页面结构

### 1. 顶部导航

顶部导航是窄而安静的金属 chrome，不承担视觉主角。

从左到右：

- SETI logo 与品牌字标。
- 语言选择。
- 文本视图开关。
- 当前页面入口，例如“任务中心”，使用底部青色线条标识选中。
- 用户账号信息与小型信息图标。

设计要求：

- 高度紧凑，约 56-64px。
- 背景比页面底色略亮，底部使用 1px 分割线。
- 不要加入大面积高亮、复杂阴影或多层导航。

### 2. Hero 任务场景

Hero 是 Home 页面最重要的氛围层。它不是独立宣传区，而是任务列表上方的环境舞台。

内容层级：

1. 小型状态标签：`可加入任务 63`，左侧短线作为仪器标记。
2. 主标题：`任务中心`，大号、厚重、白色。
3. 副标题：`探索未知，连接未来。`，低对比度灰白。
4. 主操作：`创建任务`，放在画面右侧靠下，不能抢过主标题。

画面元素：

- 白色低多边形飞船位于标题右上方，是 hero 的视觉焦点。
- 宇航员位于月面中下部，提供尺度感和叙事感。
- 橙色行星或光束在右上形成暖色对比。
- 蓝色引擎轨迹很少量出现，用来呼应可操作状态。
- 月面横向展开，形成房间卡片区域的视觉底座。

禁止：

- 不要把 hero 做成左右分栏卡片。
- 不要使用抽象渐变、光球、bokeh blob 替代真实场景资产。
- 不要写过多营销文案；Home 的任务是进入游戏，不是介绍产品。

### 3. 任务状态卡片

Hero 下方是三张状态卡，承担“快速理解当前任务池”的作用。

卡片内容：

- 状态名称：等待玩家 / 进行中 / 参与玩家。
- 大号两位数：`01` / `02` / `04`。
- 一行解释：可加入任务 / 已开始任务 / 当前任务中。
- 右上角小状态点。
- 暗色低多边形场景背景图。

视觉规则：

- 三张卡横向排列，间距一致，卡片高度稳定。
- 卡片背景图必须存在，但要压暗，不能干扰文字。
- 数字使用 Orbitron 风格，带 tabular 数字感。
- 数字颜色按状态区分：等待玩家用青色，进行中用紫色，参与玩家用绿色。
- 卡片圆角保持小半径，约 4-6px；边框为 1px 金属灰。

不要把这些卡片做成 SaaS 指标卡。它们是任务状态面板，不需要趋势图、sparkline、增长百分比或说明性长文案。

### 4. 房间筛选与房间列表

状态卡下方是实际可操作区域。筛选 tabs 必须紧贴房间列表，不要被额外介绍文字隔开。

筛选项：

- 全部
- 等待玩家
- 进行中

选中态使用底部青色线条和稍亮背景。未选中项保持低对比度。

房间卡片内容：

- 房间名或编号。
- 主持人。
- 状态标签：等待玩家 / 进行中 / 单人。
- 玩家数：例如 `1/1`、`1/2`、`2/2`。
- 模块信息：例如 `D4 · 外星模块`。

视觉规则：

- 桌面端三列卡片布局。
- 卡片背景延续暗色低多边形场景，文字区域保持可读。
- 状态标签使用语义色：进行中为橙色，等待玩家为青绿，单人为灰色。
- 房间卡片不要塞满说明文字；信息密度要高，但每行都应可扫描。

### 5. 背景元素展示区

页面下半部分的“背景元素”区域是资产库提示，也是后续页面复用的视觉素材来源。

可复用资产：

- 月面低多边形地形。
- 宇航员。
- 橙灰低多边形行星。
- 岩石 / 晶体。
- 白色飞船。
- 月面车。
- 远景设施。

这些元素应作为 SETI Home 风格的资产系统，而不是一次性装饰。后续页面可以复用同一套资产来保持统一，但每个页面的资产密度要按功能减少，避免喧宾夺主。

## 字体与文字气质

建议字体方向：

- 英文品牌、数字、短标签：Orbitron。
- 中文正文、按钮、房间信息：Noto Sans SC。
- 密集技术数据才使用等宽字体；Home 页面大多数数字不需要等宽字体。

文字风格：

- 标题短而直接，例如“任务中心”。
- 副文案克制，例如“探索未知，连接未来。”。
- 按钮使用真实动作，例如“创建任务”。
- 状态文案描述真实任务状态，不要写“启动协议”“进入星门”这类泛化科幻词。

## 交互与动效

Home 页面应感觉稳定、安静、可操作。动效只用于帮助用户理解状态。

建议：

- 页面加载时，hero 场景轻微淡入，卡片做短延迟出现。
- 状态点可以有很轻的呼吸，但只在实时状态活跃时使用。
- hover 时卡片边框略亮，背景图轻微提亮。
- 主按钮 hover 时增加 4-6% 亮度，不做大面积外发光。

禁止：

- 不要让星星闪烁。
- 不要做飞船大幅移动或循环动画。
- 不要给每个卡片都加发光边框。
- 不要使用 bounce / elastic 动效。

## 响应式原则

桌面是主要体验，但布局需要能收缩：

- 顶栏在窄屏上保留 logo、当前页、关键操作，账号和语言可折叠。
- Hero 高度可以降低，但必须保留标题、创建任务按钮和至少一个关键场景资产。
- 三张状态卡在中等宽度下变成两列或一列。
- 房间卡片从三列降到两列、一列。
- 背景元素区在移动端可以隐藏部分资产，但不要隐藏任务列表。

## 后续实现验收清单

- 首屏能同时看到：任务中心标题、创建任务按钮、三张状态卡、房间筛选或房间列表顶部。
- 页面背景不是纯黑，能看出星空和月面层次。
- Hero 有真实场景资产：飞船、月面、宇航员或等价 SETI 场景元素。
- 任务状态卡不是普通白字黑卡，而是带暗色场景图、状态点和语义色数字。
- 房间列表信息可快速扫描：名称、主持人、状态、玩家数、模块信息齐全。
- 青色只用于可操作/选中/可加入，橙色只用于进行中或行星暖色焦点。
- 字体层级明确：大标题、状态数字、房间正文、标签各自有稳定样式。
- 没有营销式 hero、SaaS 指标趋势图、抽象渐变球、泛化终端文案。
