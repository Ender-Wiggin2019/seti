## Critical Issues

### C-01: Event display cap could drop uncommitted turn events

**Files:** `packages/server/src/engine/event/EventLog.ts`, `packages/server/src/gateway/GameManager.ts`
**Dimension:** Logic Correctness
**Status:** Fixed

`EventLog` capped stored events at append time, but the new turn-complete persistence boundary commits `eventLog.since(lastCommittedSeq)` only after a turn fully settles. A long turn with more than the display window could silently lose early events before they were persisted.

**Fix:** Keep full runtime event history in `toArray()` / `since()` and apply the configured cap only through `recent(count)`.

**Coverage:** Added/updated `EventLog` and `GameManager` regression tests proving turn events beyond the display window still commit.

### C-02: Local E2E scripts could use ambient `DATABASE_URL`

**Files:** `scripts/init-e2e-local.sh`, `scripts/run-e2e-local.sh`
**Dimension:** Quality / Safety
**Status:** Fixed

The local E2E scripts set `PGDATABASE=seti_e2e`, but an exported `DATABASE_URL` could still override the intended database in Node/Postgres clients. That made accidental writes to a developer database plausible.

**Fix:** Added `E2E_DATABASE_URL` as the explicit override, fail-fast guards for ambient `DATABASE_URL`, and subshell isolation that unsets ambient DB URLs before preparation, server startup, and Playwright.

**Coverage:** Added static script regression checks in `runE2eLocalScript.test.ts`.

## Warnings

### W-01: Trace slot helper targeted the wrong selector

**File:** `packages/e2e/helpers/prompt-resolvers.ts`
**Dimension:** Logic Correctness
**Status:** Fixed

`clickInputOptionById` looked for a generic prompt option selector instead of the rendered trace slot button, so real board trace selection could fall back to the wrong path.

**Fix:** The helper now targets `data-testid="trace-slot-${optionId}-button"` and `data-server-trace-slot-id="${optionId}"`.

### W-02: Skipping self animations could clear active opponent render state

**Files:** `packages/client/src/features/board/animation/animationController.ts`, `packages/client/src/features/board/animation/useAnimationQueue.ts`
**Dimension:** Logic Correctness
**Status:** Fixed

When a self-authored batch was skipped while an opponent animation was active, the hook dispatched `completeBatch`, which cleared shared active render state.

**Fix:** Added `markBatchComplete`, which records completion without clearing the active batch, probe overrides, or disc overrides.

**Coverage:** Added reducer and hook regression tests for skipped self batches during active opponent animation.

### W-03: Lobby/Home player telemetry counted only the first page

**Files:** `packages/server/src/lobby/lobby.service.ts`, `packages/server/src/lobby/dto/RoomResponseDto.ts`, `packages/client/src/api/lobbyApi.ts`, `packages/client/src/pages/home/HomePage.tsx`, `packages/client/src/pages/lobby/LobbyPage.tsx`
**Dimension:** Logic Correctness
**Status:** Fixed

The UI summary fetched only page 1 and summed players from that page, undercounting active players when matching rooms exceeded one page.

**Fix:** Added `totalPlayers` to paged room-list responses. The server aggregates all players across the current filter, and Home/Lobby consume that aggregate.

**Coverage:** Added API and service tests for paged responses and aggregate player counts.

### W-04: Legacy room-list API assumed the old array contract

**File:** `packages/client/src/api/lobbyApi.ts`
**Dimension:** Maintainability
**Status:** Fixed

`listRoomsLegacy` still called `/lobby/rooms` and assumed the response was an array, which crashes against the new paged contract.

**Fix:** `listRoomsLegacy` now delegates to `listRooms()` and returns `.items`.

**Coverage:** Added a regression test using a paged server response.

### W-05: Scene sprite script lacked a dependency preflight

**Files:** `scripts/process-seti-scene-sprite.mjs`, `packages/client/__tests__/scripts/processSetiSceneSprite.test.ts`, `.impeccable.md`
**Dimension:** Quality / Maintainability
**Status:** Fixed

The sprite generator failed only at the first `cwebp` invocation when WebP tools were missing. The generated `terrain_*` and `objects_*` files are intentionally identical legacy aliases from one v2 sheet, but the docs did not say that clearly.

**Fix:** Added a `cwebp -version` preflight before writing files, added a missing-dependency test, and documented the dual-prefix alias intent.
